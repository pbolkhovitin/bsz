# Сводка сканирования

## Методология

Сканирование выполнялось с машины `tpt14g1-fedora` (Fedora, nmap 7.92) с правами root.
Обе подсети обслуживаются одним физическим интерфейсом `enp5s0`, на котором сконфигурированы
адреса **192.168.40.254/24** и **192.168.41.254/24** (обе подсети находятся в одном L2-сегменте).

### Параметры сканирования

| Этап | Команда | Результат |
|------|---------|-----------|
| Discovery | `nmap -sn <подсеть>` | 40.x: 110 up, 41.x: 123 up |
| Порты/службы | `nmap -sS -sV --version-light -T4` | Полный список открытых TCP-портов и версий служб |
| Идентификация MAC | `ip neigh`, OUI-базы IEEE (MA-L) + nmap | Вендоры по MAC-адресам |

Сканирование проводилось по списку живых хостов, полученных на этапе discovery.

## Примечания и ограничения

1. **Большое число "Embedded/Other" в .40** — устройства с открытым портом 80/443, не
   классифицированные как камеры/принтеры. Требуют ручного уточнения (могут быть МФУ,
   IP-камеры, точки доступа, ИБП и пр.).
2. **"Unidentified" (26)** — хосты без открытых TCP-портов. Могут быть спящими рабочими
   станциями, мобильными устройствами, либо устройствами, отвечающими только по UDP.
3. **Порт 7070 (realserver)** — присутствует на многих Windows-хостах обоих сегментов.
   Предположительно специфическое ПО (взаимодействие с промышленными контроллерами/камерами).
   Требует уточнения.
4. **Шлюз сегмента .41** не обнаружен в ARP/nmap как отдельный хост `.41.1` (не отвечал).
   Оба сегмента в одном L2 — вероятно, маршрутизация/шлюз обеспечивается тем же устройством
   (192.168.40.1) или отдельным коммутатором. Требует уточнения.
5. **Определение ОС (nmap -O)** не выполнялось в полном объёме на всех хостах — тип ОС
   определён косвенно по открытым службам (SMB/RDP/HTTP-баннерам).
6. MAC-адреса с локальным битом (рандомизация) не определяются по OUI-базе.
